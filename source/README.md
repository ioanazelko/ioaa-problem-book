# IOAA Problems by Topic — build source

The book is **not** LaTeX. It is generated by a Python script using
[PyMuPDF](https://pymupdf.readthedocs.io/), which:

1. draws the page furniture (titles, chapter/section/problem headers, rules,
   page numbers, contents, index) directly onto blank A4 pages, and
2. stamps each problem statement in as a **vector crop of the original IOAA
   PDF** via `Page.show_pdf_page(..., clip=...)`.

Nothing is retranscribed or re-typeset, so figures, tables, fonts and equations
are pixel-for-pixel the official papers. The trade-off is that the problem text
itself cannot be reflowed or restyled — a crop is a rectangle of someone else's
page. That is why the layout code only controls what sits *around* each crop.

## Requirements

    pip install pymupdf

## The source PDFs

The official IOAA problem and solution papers are kept outside this repository
in the sibling directory `../IOAA Source Papers/`. It holds 103 theory and
data-analysis PDFs and 70 observation-round PDFs under `observation/`.

All source-paper tools resolve that location relative to the repository. Set
`IOAA_PAPERS_DIR` to an absolute path to use an archive stored elsewhere.

## Files

| File | Role |
|---|---|
| `../IOAA Source Papers/` | External archive containing the 103 official IOAA theory and data-analysis source PDFs. |
| `../IOAA Source Papers/observation/` | External archive containing 70 observation-round PDFs (planetarium, sky map / naked eye, telescope, night and day), 2007-2025. The crop book does not use them. |
| `paper_paths.py` | Resolves the external archive, with an `IOAA_PAPERS_DIR` override. |
| `classify_obs.tsv` | 74 observation problems classified into the same 14 chapters, with round codes `OBS-PLAN` / `OBS-SKY` / `OBS-TEL`. Used by the LaTeX edition only. |
| `classify_*.tsv` | The editorial content. One row per problem: `year, round(TH/DA), label, title, points, chapter(1-14), tag, secondary-chapter`. 326 rows. **Edit these to re-file a problem into a different chapter, retitle it, or change its order.** |
| `build_config.py` | Generates `config_all.json`: the anchor regexes / page ranges that say where each problem starts and ends inside each source paper. |
| `config_all.json` | Generated output of the above. |
| `split_pdf.py` | Turns `config_all.json` into `snippets/manifest.json`. |
| `snippets/manifest.json` | The crop table: `{snippet_id: [[source_pdf, page_0based, y_top, y_bottom], ...]}`. Ids look like `2016_TH_T3` (problem) and `2016_THSOL_T3` (solution). 652 entries. |
| `assemble_book.py` | The book assembler — layout, headers, TOC bookmarks, cross-references, front matter, index by year. |

## Rebuilding

Regenerate the crop table (only needed after editing `build_config.py`):

```bash
python build_config.py && python split_pdf.py config_all.json snippets --dry
```

Assemble the book:

```bash
python assemble_book.py
```

This writes `IOAA_Problems_by_Topic_2007-2025.pdf` (~178 MB uncompressed,
1366 pages). It runs the layout **twice**: pass 1 learns which page every
problem and solution lands on, pass 2 re-lays it out with the
`[sol. p. N]` / `[problem p. N]` cross-references filled in.

To get the shipped 116 MB file:

```python
import pymupdf
d = pymupdf.open('IOAA_Problems_by_Topic_2007-2025.pdf')
d.save('out.pdf', garbage=4, deflate=True, deflate_images=True,
       deflate_fonts=True, clean=True)
```

## How the layout works

`assemble_book.py` is one class, `Book`, holding a cursor `self.y` down the
current page:

- `chapter()` / `section()` / `problem_header()` — draw furniture, advance `y`.
- `place_segments()` — for each `[pdf, page, y0, y1]` in a manifest entry,
  compute a tight horizontal bbox (`seg_bbox`, which unions text blocks,
  images and vector drawings so margins are trimmed but nothing is clipped),
  scale it to the text width, and stamp it.
- Two known layout hazards, both fixed and worth preserving if you edit this:
  - **Stranded headers.** A header must be laid out together with its first
    crop, otherwise a tall crop breaks to the next page and leaves the header
    alone on an empty one. `problem_header()` takes the segment list and
    pre-computes whether the first crop fits.
  - **Float dust.** A crop whose scaled height equals the available space to
    within ~1e-13 pt used to fail the `>` test and get pushed off the page
    entirely, silently rendering a blank solution. Both fit tests carry a
    0.5 pt tolerance. If solutions ever come out blank again, look here first.

`seg_bbox` falls back to full page width when it finds little content, which is
what makes the scanned 2009/2011/2012 solution files work.

## Known caveats (also stated in the book's front matter)

- Observation, planetarium and team rounds are excluded.
- 2010, 2013, 2020: no separate problem paper survives; statements are cropped
  from the solution files.
- 2009, 2011, 2012 solutions are scans; where two solutions share a page, the
  neighbouring one is visible in the crop.
- 2014 data analysis: the official solutions pair "Problem 3" A and B, so the
  same crop serves D2 and D3.
- 2021 pages carry their own banner strip, which sits just below the book's
  problem header and slightly crowds it. Cosmetic only; fixing it would mean
  re-cutting every 2021 anchor.

## Structure changes since the first build

- Gravitational-wave problems were split out of chapter 10 into their own
  **chapter 14**, so the topic has room to grow as new olympiads add problems.
  Five problems moved: 2016 T11, 2021 Q1, 2022 DA1, 2023 Q13, 2025 T03.
- Solutions now follow **each chapter** rather than sitting in a single Part II
  at the back, so a problem and its answer stay together.
